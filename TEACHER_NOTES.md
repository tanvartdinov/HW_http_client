# Примечания преподавателю

Обязательная часть — надёжный API-клиент; BeautifulSoup и Playwright остаются необязательными. Основное ТЗ выдаётся студентам как HOMEWORK.md вместе с CONTRACT.md и файлами комплекта. Эталонного решения нет: студент выбирает архитектуру, места перехвата исключений, классы ошибок и формат отчёта.

В комплекте сервис уже содержит 36 событий. Проверка поиска «джаз» должна дать ID 1, 10, 34. Главная надпись обновлена на 36. README исходного сервиса актуализирован для расширенного набора; контракт ДЗ находится отдельно в CONTRACT.md.

Разрешены тесты или воспроизводимые демонстрации, но демонстрации должны показывать число запросов и проверять заданные последовательности. Не требуйте от новичка знания pytest, если оно ещё не изучалось: достаточно unittest.mock и assert в отдельном скрипте.

Принципиальные уточнения брифа:

1. 429 относится к 4xx: обязательное задание запрещает его ретрай даже при Retry-After. Заголовок сохраняется для диагностики. Не оценивать отсутствие ожидания как ошибку.
2. Токен серверу не нужен. Проверяется конфигурация и условная передача заголовка, а не полноценная авторизация.
3. 400 и изменяемые последовательности представлены fixtures. В реальном сервисе есть 404/422 и постоянные учебные ошибки; не обещать студентам эндпоинт, который сам выздоровеет после двух ошибок.
4. Обычная афиша статическая. Для Playwright добавлена отдельная /static/dynamic.html с JS-загрузкой и состояниями loading/loaded/error; менять сервер не требуется.
5. JSON-fixtures — конверты HTTP-ответов с body_text строкой, а не файлы, непосредственно подаваемые в валидатор EventList.

Перед выдачей разместите рядом с заданием лонгрид занятия о Selenium и Playwright и добавьте ссылку на него в LMS. В брифе ссылка не указана, поэтому она не выдумана в ТЗ; дополнительно дана официальная инструкция Playwright.

Рекомендуемый порядок ревью: воспроизвести установку → два успешных сценария → пустая выдача → 404/429 без повторов → 500 и Timeout с ограничением → невалидные данные → сверить число попыток → проверить README. Для бонусов отдельно проверить явную ошибку изменённой HTML-структуры и динамическое ожидание.
